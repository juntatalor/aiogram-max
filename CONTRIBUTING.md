# Как поучаствовать

Библиотека покрывает не весь Telegram Bot API, и это осознанно: методы
добавляются по мере надобности. Если вам не хватило какого-то — скорее всего,
он уже помечен как «ждём PR».

## Что означает ошибка, которую вы поймали

* `NotImplementedYet` — **аналог в MAX есть, мы его не написали**. В тексте
  ошибки лежит подсказка, каким методом MAX это делается. Такой PR приветствуется
  и обычно занимает несколько десятков строк.
* `UnsupportedByMax` — **у платформы нет такой возможности**. Опросов и
  игральных костей в MAX нет, PR тут не поможет.

Список первого вида — в `NOT_IMPLEMENTED_PR_WELCOME` (`src/aiogram_max/session.py`).

## Добавить метод

1. Напишите обработчик в `MaxSession` и зарегистрируйте его в `_HANDLERS`.
   Обработчик обязан вернуть ровно тот тип, который объявлен у метода aiogram
   в `__returning__` — иначе сломается типизация на стороне бота.
2. Уберите метод из `NOT_IMPLEMENTED_PR_WELCOME`.
3. Тест обязателен. Фейковый MAX (`FakeMax` в `tests/test_session.py`) отвечает
   на новый путь — добавьте туда ветку и проверьте **тело запроса**, а не только
   факт вызова: половина расхождений с MAX — именно в полях.
4. Если параметр Telegram при переводе теряется — сообщите об этом через
   `self._degrade(...)`. Молча выбрасывать нельзя.

## Проверки

```bash
uv venv && uv pip install -e ".[dev]"
.venv/bin/ruff check . && .venv/bin/ruff format --check .
.venv/bin/mypy
.venv/bin/pytest -q
```

Всё это гоняется в CI на Python 3.12, 3.13 и 3.14.

## О тестах на живых данных

`tests/fixtures/live_max_updates.json` — обезличенные события, снятые с
настоящего MAX Bot API. Тесты на них (`tests/test_live_fixtures.py`) ловят то,
чего не поймает фейк: расхождение между документацией и реальным поведением.
Один такой баг уже нашёлся — `recipient.user_id` оказался получателем
сообщения, а не собеседником, и id бота едва не утёк в `Chat.id`.

Если ловите новое событие от живого MAX — обезличьте и добавьте в фикстуры.
